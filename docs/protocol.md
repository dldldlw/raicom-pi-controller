# 串口通信协议

树莓派与 K230 之间通过串口通信：**树莓派侧 `/dev/ttyUSB0`，K230 侧 UART2**
（TXD = GPIO11，RXD = GPIO12），波特率 **115200**，8N1。

数据格式极简：**每个指令就是一个字节，没有帧头、没有长度、没有校验和**。

> ⚠️ 因为没有帧头和校验，上电瞬间的线路噪声有可能被当成合法指令执行。
> 如果要长期使用，建议改成 `[0xAA][CMD][CHECKSUM]` 的帧格式。
> 当前版本保持原样，是为了与赛场上验证过的固件保持一致。

## 指令表

| 字节 | 方向 | 名称 | 触发条件 / 含义 | 树莓派侧动作 |
|---|---|---|---|---|
| `0xAA` | 树莓派 → K230 | `READY` | 树莓派启动完成后握手 | 启动 `sleep(3)` 后发送一次 |
| `0x0B` | K230 → 树莓派 | `MOTOR2_REV` | 目标偏右，`H > +30` px | 左右电机反转 50 步 |
| `0x0C` | K230 → 树莓派 | `MOTOR2_FWD` | 目标偏左，`H < -30` px | 左右电机正转 50 步 |
| `0x0D` | K230 → 树莓派 | `MOTOR1_REV` | 目标偏下，`V > +30` px | 上下电机反转 50 步 |
| `0x0E` | K230 → 树莓派 | `MOTOR1_FWD` | 目标偏上，`V < -30` px | 上下电机正转 50 步 |
| `0xFF` | （预留） | `START_GRAB` | 启动红外触发夹取流程。**比赛中未使用此字节** | 前后电机前进，红外触发后夹取 5 次 |
| `0xCC` | K230 → 树莓派 | `DONE` | 目标已居中（`\|H\|` 和 `\|V\|` 均 < 30 px） | 三个电机失能；`EXIT_ON_TARGET_CENTERED=True` 时退出主程序 |

其中 `H` / `V` 的定义（单位：像素，均在 1920×1080 的显示坐标系下）：

```
H = 检测框中心 x - 画面中心 x      H > 0 表示目标在画面中心右侧
V = 检测框中心 y - 画面中心 y      V > 0 表示目标在画面中心下侧
```

## 时序

```
树莓派                                    K230
  |                                         |
  |-- 初始化 GPIO / 串口 ------------------|
  |                                         |-- 加载 kmodel、初始化 Sensor
  |   sleep(3)  等待 K230 上电启动           |
  |----- 0xAA (READY) -------------------->|   (当前未读取，见下)
  |                                         |
  |<---- 0x0B / 0x0C / 0x0D / 0x0E --------|   每 200 ms 最多发一组
  |      每个字节走 50 步，耗时约 10 ms      |
  |                                         |
  |<---- 0xCC (DONE) ----------------------|   目标居中，退出循环
  |  失能电机、可选退出                       |
```

发送侧限频：K230 每 **200 ms** 最多发送一组方向指令（`SEND_INTERVAL`），
避免每帧都发导致下位机被指令淹没、来不及走完步数。

## 已知的协议缺口

这几条在原始版本里是**断的**，请在复用时注意：

1. **`0xAA` 握手是单向的。** 树莓派发出去，但 K230 侧的
   `det_center_align_uart.py` 从不调用 `uart.read()`，所以这个字节一直躺在
   K230 的接收缓冲里。也就是说，树莓派"我准备好了"这个信息实际没有被使用，
   K230 无法确认下位机已就绪就开始发指令。本仓库保留了该行为（不影响比赛），
   要真正用起来需要在 K230 侧加一段"等 0xAA 再进主循环"。

2. **`0xFF`（启动夹取）是预留字节，比赛中从来没被真正用过。**
   五个 K230 源文件都不发这个字节 —— 因为实际的红外夹取根本**不走串口**：
   当时是在树莓派上**直接调用 `handle_motor3_with_sensor()`** 触发的
   （比赛时在 REPL 里手动敲进去）。

   所以这个 `0xFF` 分支是一段**可达但未被使用的死入口**。保留它是因为串口入口
   本身是完整的、将来可能用得上；同时新增了
   [`tools/trigger_grab.py`](../tools/trigger_grab.py)，
   把当年"REPL 手敲函数调用"这个操作固化成可复现的脚本。

3. **`0xCC` 原来被静默丢弃。** 原 `main.py` 的 if/elif 链里没有 `0xCC` 分支，
   K230 的收工信号对树莓派完全无效。本版本已经补上处理分支
   （失能电机 + 按 `config.EXIT_ON_TARGET_CENTERED` 决定是否退出）。
