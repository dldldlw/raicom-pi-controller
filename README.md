# RAICOM 睿抗机器人开发者大赛 · 树莓派下位机

2025 年睿抗机器人开发者大赛（RAICOM）国赛参赛作品 —— **执行机构控制端**。

树莓派通过串口接收 K230 视觉模块发来的单字节指令，驱动**三轴步进电机**
把目标"搬到"画面中心；**红外触发的舵机夹爪**则是一条独立的本地链路。

> 作者：**[dldldlw_逐风](https://github.com/dldldlw)**
>
> 配套的上位机视觉代码见另一个仓库 **raicom-k230-vision**。

> ### ⚠️ 关于本仓库代码的来源
> 比赛期间代码是**直接在树莓派上编辑**的（没有在 PC 上写完了再拷过去）。
> 本仓库整理自赛后留存的 **PC 副本**，而树莓派上当时跑的那一份可能有后续改动
> 没能同步回来。因此这里的代码**以 PC 副本为准**，可能与比赛现场实际运行版本
> 存在差异。如果有出入，以现场版本为准。

## 系统架构

```
┌──────────────────────────┐                ┌──────────────────────────────┐
│   K230 (上位机 / 视觉)     │                │   树莓派 (下位机 / 执行)        │
│                          │                │                              │
│  Sensor ──┬─ CHN0 ──► 显示 │                │  ┌─ 上下电机 (ENA/DIR/PUL)     │
│           └─ CHN2 ──► AI   │                │  ├─ 左右电机 (ENA/DIR/PUL)     │
│              │            │   串口 115200   │  ├─ 前后电机 (ENA/DIR/PUL)     │
│         ai2d 预处理        │  ───────────►  │  └─ TCRT5000 + 舵机夹爪        │
│              │            │  0x0B/0C/0D/0E  │                              │
│         KPU 推理          │  0xFF / 0xCC    │   接收指令 → 走固定步数          │
│              │            │  ◄───────────  │                              │
│      目标相对中心的 H/V 偏移 │      0xAA       │                              │
└──────────────────────────┘                └──────────────────────────────┘
```

**控制闭环**：K230 算出目标相对画面中心的像素偏移 → 发方向字节 → 树莓派走
50 步 → K230 重新检测 → 直到偏移进入 ±30 px 死区 → 发 `0xCC` 收工。

## 硬件清单

| 部件 | 说明 |
|---|---|
| 主控 | Raspberry Pi（任意带 40 pin GPIO 的型号） |
| 步进电机 ×3 | 42 步进电机 + TB6600 / DM542 类驱动器（ENA / DIR / PUL 三线接法） |
| 机械结构 | 三轴滑台：上下（垂直）、左右（水平）、前后（进给） |
| 传感器 | TCRT5000 反射式红外对管 |
| 执行器 | 舵机夹爪（50 Hz PWM 控制） |
| 通信 | USB 转串口，连接 K230 的 UART2 |

完整引脚接线见 **[docs/wiring.md](docs/wiring.md)**。

## 快速开始

### 1. 安装依赖

```bash
# 树莓派 (Raspberry Pi OS)
sudo apt update
sudo apt install -y python3-pip
pip3 install pyserial

# RPi.GPIO 通常系统自带；若使用较新内核且 GPIO 不可用，改用 rpi-lgpio:
#   pip3 install rpi-lgpio
```

### 2. 确认串口设备名

```bash
ls /dev/ttyUSB*        # 通常是 /dev/ttyUSB0
groups | grep dialout  # 没有的话: sudo usermod -aG dialout $USER 然后重新登录
```

如果设备名不是 `/dev/ttyUSB0`，改 `config.py` 里的 `SERIAL_PORT`。

### 3. 运行

```bash
sudo python3 main.py
```

程序启动后会 `sleep(3)` 等待 K230 上电，然后发送 `0xAA` 就绪信号，
之后进入主循环等待指令。`Ctrl+C` 可安全退出（会关闭串口并清理 GPIO）。

### 4. 单独自测各模块

```bash
sudo python3 stepper_motor.py   # 逐个点动电机，含加减速测试
sudo python3 jg_cgq.py          # 红外对管监控 + 舵机夹取循环
```

两个自测块都从 `config.py` 读引脚，不会再出现撞脚问题。

## 指令表速查

| 字节 | 方向 | 含义 |
|---|---|---|
| `0xAA` | 树莓派 → K230 | 就绪握手 |
| `0x0B` / `0x0C` | K230 → 树莓派 | 目标偏右 / 偏左，左右电机反转 / 正转 50 步 |
| `0x0D` / `0x0E` | K230 → 树莓派 | 目标偏下 / 偏上，上下电机反转 / 正转 50 步 |
| `0xCC` | K230 → 树莓派 | 目标已居中，电机失能并收工 |
| `0xFF` | （预留，比赛中未用） | 串口入口：启动"前后电机前进 + 红外触发夹取"流程 |

完整说明（含偏移量定义、时序图、协议缺口）见 **[docs/protocol.md](docs/protocol.md)**。

> **关于 `0xFF`**：这个字节在本工程里**从未被真正发送过**。当年的红外夹取是
> 在树莓派上**直接调用 `handle_motor3_with_sensor()`** 触发的（比赛时在 REPL 里
> 手敲函数调用），完全没走串口。串口入口保留备用，逻辑是完整可用的。

## 红外夹取怎么触发

这条链路**不依赖 K230，也不走串口**。当时的做法是在树莓派上直接调函数，
现在固化成了脚本：

```bash
sudo python3 tools/trigger_grab.py
```

它会初始化"前后电机 + 红外对管 + 舵机"，调用 `handle_motor3_with_sensor()`
（电机持续前进 → 红外检测到电平变化 → 再前进 100 步 → 夹取 5 次），
结束后清理 GPIO。`Ctrl+C` 可中断。

如果你确实想走串口路径，往 `/dev/ttyUSB0` 写一个字节 `0xFF` 效果完全相同。

## 关键实现说明

### `config.py` 为什么单独存在

原始工程把引脚号散落在三个文件里，导致同一个引脚出现互相矛盾的默认值：

| 文件 | 写法 | 结果 |
|---|---|---|
| `main.py` | `SERVO_PIN = 4` | 因为原 18 与上下电机 DIR 冲突，已改正 |
| `jg_cgq.py` | `SERVO_PIN = 18` | 自测块没跟着改 ❌ |
| `stepper_motor.py` | `dir_pin=18` | 自测块里的电机占用同一脚 ❌ |

单独跑后两个文件的自测块时，舵机会和上下电机的方向脚抢引脚。
现在所有引脚只在 `config.py` 定义一次，改接线只改一个文件。

### 步进电机驱动

`StepperMotor.rotate()` 用软件延时 bit-bang 生成脉冲，实现简单、不依赖
硬件 PWM；缺点是受 Python 调度抖动影响，`delay` 很小时会丢步。

`rotate_soft()` 提供了指数曲线的加减速（`max_delay * exp(-3.5r)`），
用于降低高速段的失步概率。**当前 `main.py` 没有使用它**（仍走硬启停），
保留作为后续提速的备选。

### 红外触发夹取流程

`handle_motor3_with_sensor()`：前后电机以最短脉冲间隔持续前进，同时以同频率
轮询红外对管的电平变化；检测到变化后再前进一段距离，然后执行 5 次"夹紧—松开"。

> ⚠️ 这个函数是**阻塞**的。抓取全过程约 `5 × 0.9s ≈ 4.5s`，期间主循环无法
> 响应其它串口指令。比赛流程如果需要并发，应改写成非阻塞状态机。

## 已知问题

这份清单是诚实的自我记录 —— 其中一部分是**为了不改变赛场上验证过的行为而
刻意保留**的，都标注了如何修改。

| 严重度 | 问题 | 位置 | 说明 |
|---|---|---|---|
| 中 | 抓取流程阻塞主循环约 4.5 s | `main.py` `handle_motor3_with_sensor()` | 抓取期间无法响应其它指令。需要并发就得改成状态机 |
| 中 | `GRAB_PAUSE_AFTER = 2` 的来历可疑 | `config.py` | 原代码硬编码 `if i < 2`，在 3 次循环里等于"最后一次不暂停"；循环改成 5 次后没跟着改，属复制粘贴残留。**为不改变赛场计时，保留了原行为**。想改成"每次之间都暂停"就设为 `4` |
| 中 | 舵机到位后占空比归零，失去保持力矩 | `jg_cgq.py` `set_servo_angle()` | 原行为，用于消除舵机吱吱声。夹紧状态下可能被工件顶开，需要保持力矩就把构造参数的 `hold_torque=True` |
| 中 | 无帧头 / 无校验和的裸字节协议 | 全局 | 上电噪声可能被当成指令。要长期使用建议改成 `[0xAA][CMD][CHECKSUM]` |
| 低 | `0xFF`（启动夹取）是未被使用的死入口 | `main.py` `CMD_START_GRAB` | 实际的红外夹取是当年在 REPL 里**直接调 `handle_motor3_with_sensor()`** 触发的，不走串口，所以这个字节从未被发送过。串口入口本身完整可用，保留备用；已新增 `tools/trigger_grab.py` 把当年的手动操作固化下来 |
| 中 | `0xAA` 握手是单向的 | `docs/protocol.md` | K230 侧从不 `uart.read()`，该信号实际未被使用 |
| 低 | 无位置反馈，固定 50 步/指令 | `config.py` | 无法"走到位"，复位依赖人工；控制律是纯 bang-bang |
| 低 | 红外触发无去抖 | `jg_cgq.py` `check_trigger()` | 默认 `debounce_count=1` 与原行为一致；遇噪声误触发可调大到 3~5 |
| 低 | `rotate_soft()` 未被使用 | `stepper_motor.py` | 已实现但 `main.py` 走硬启停 |
| 低 | `GPIO.setmode()` 被每个实例重复调用 | `stepper_motor.py` | 幂等，无实际影响 |

**本次相对原始版本已修复的：**

- ✅ 补上 `0xCC` 的处理分支（原版**没有这个分支**，K230 的收工信号被静默丢弃）
- ✅ 修正注释与代码不符：原注释"延时0.2秒"实为 100 步 ≈ **0.02 秒**；原注释"三次夹取"实为 `range(5)` **五次**
- ✅ 引脚统一到 `config.py`，消除三处互相矛盾的默认值（含 GPIO18 冲突）
- ✅ 串口打开失败时给出可操作提示，而非直接抛 traceback
- ✅ 加 `if __name__ == "__main__"` 守卫，`import main` 不再初始化硬件
- ✅ 退出时补上全局 `GPIO.cleanup()`（原来步进电机的引脚从未被清理）
- ✅ 删掉从未被使用的 `trigger_duration_ms` 死参数
